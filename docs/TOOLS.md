# Tools reference

The 41 MCP tools exposed today (22 read-only, 19 not read-only: 18 write to the ALM, plus `download_attachment`, which writes a local file). All are async and validated through the `@tool` boundary
(invalid input or domain failures surface as `ToolError`). `domain` is one of `rm`, `ccm`, `qm`.
See `docs/USAGE.md` for query syntax and examples.

## Read

| Tool | Signature | Description |
|------|-----------|-------------|
| `list_projects`     | `(domain)` | List projects (service providers) for a domain. |
| `search_requirements` | `(project, query=None, limit=None)` | OSLC query over RM requirements (DOORS Next). The project's stream (service provider → `oslc_config:component` → `oslc_config:configurations` → first `rdfs:member`) is sent as `Configuration-Context`, with `oslc.prefix` (dcterms, oslc, rdf, nav, jazz_rm) and `oslc.select`; a project without a stream is queried without the header. Follows the pages until `limit` items (default and maximum 1000). Returns `{"items": [{"uri", "title", "identifier", "type", "modified", "folder"?}], "truncated": bool, "total"?: int, "configuration"?: stream URI}`: one item per requirement; `total` comes from `oslc:totalCount` or the title "Query Results: N". `limit <= 0` is refused. |
| `get_requirement`   | `(uri)` | Fetch a single requirement by its OSLC URI. RM answers HTTP 415 to JSON, so it falls back to `application/rdf+xml` and returns a flat dict (`rdf:about`, `prefix:name` -> text, XML string for `parseType="Literal"`, or URI; repeated properties become lists). |
| `list_workitems`    | `(project, query=None, limit=None, type=None, state=None, owner=None, planned_for=None, include_hidden=False)` | OSLC query over CCM work items. Optional filters, applied by the server in `oslc.where` and combined with `query` by `and`: `type` (id, alias or title, resolved by the project's discovery and sent as `rtc_cm:type="<id>"`), `state` (state id sent as `rtc_cm:state`, see `list_workflow`; a state title is accepted only together with `type`, resolved by that type's workflow, otherwise an error asks for the id), `owner` (user id or URI, always sent as a URI, `dcterms:contributor`), `planned_for` (iteration URI, `rtc_cm:plannedFor`); a filter value with a quote, angle bracket, backslash or non-printable character is refused before any request; the raw `query` is joined to the filters only with `and` (no `or`). `include_hidden=false` leaves out, on the client, the states the local profile lists in `hidden_states` (never when a `state` filter is given; no profile, nothing hidden). Results follow the server's pages until `limit` items (default 50, maximum 1000, no duplicates). Returns `{"items": [{id, title, type, status, owner}], "truncated": bool}`; `truncated=true` means the query has more items. An expired session is re-authenticated once per page; a page that keeps failing raises an error naming the gate and how many items had been collected. |
| `get_workitem`      | `(id)` | Fetch a single work item by ID. |
| `search_testcases`  | `(project, query=None)` | One item per ETM test case (`{uri, title, identifier, short_id, state, type}`); the TestCase query capability is chosen by `oslc:resourceType`, RDF/XML only. Follows the pages up to 1000 items; returns `{"items": [...], "truncated": bool}`. |
| `list_qm_resources` | `(project, type, query=None, limit=None)` | Resources of one of the 14 ETM types (case-insensitive), paged with `oslc_qm.pageSize`; default 50, maximum 1000. Returns `{"items": [...], "truncated": bool, "total": oslc:totalCount or null}`. |
| `get_qm_resource`   | `(uri)` | One ETM resource: `{uri, type, title, identifier, short_id, state, links}`; `links` groups target URIs (`validates_requirement`, `tests_change_request`, `uses_test_script`, `runs_test_case`, `executes_test_script`, `test_results`). |
| `get_test_coverage` | `(project)` | Per test case, the requirements it validates and the work items it tests (from the links inline in the listing). Returns `{"items": [{uri, title, short_id, requirements, work_items}], "truncated"}`. |
| `get_test_results`  | `(project, test_case=None)` | Test results: `{uri, title, verdict, verdict_name, points: {passed, failed, blocked}, execution_record, test_case}`; `verdict` is the URI of the verdict resource (`.../ExecutionResult#com.ibm.rqm.execution.common.state.inconclusive`), `verdict_name` its readable final fragment (`inconclusive`); zeroed points come as `0`; `test_case` (a TestCase URI) filters client-side, after reading at most 1000 results (a case whose results lie beyond that is not found; `truncated` tells). Property names confirmed in live reading. |
| `list_iterations`   | `(project)` | List a project's iterations (title, dates, URI). |
| `list_comments`     | `(id)` | Comments of a work item (`oslc:discussedBy` -> `oslc:comment`), in thread order: `[{"id", "author", "created", "text"}]`. An item without discussion returns `[]`. |
| `list_workflow`     | `(project, type, refresh=False)` | Workflow of a work item type (`type` as in `create_workitem`): `{"type", "workflow", "states": [{"id", "title", "group"}], "actions": [...]}`. The action ids are what `transition_workitem` accepts. `refresh=true` ignores the discovery cache. A type whose shape does not expose its workflow is an error. |
| `get_plan_items`    | `(project, plan=None, item_ids=None)` | Hierarchical view: backlog items with child tasks expanded in one call. Select by `plan` (iteration title substring) or `item_ids`. The result carries `truncated` (true when the backlog query had more than 1000 items). |
| `list_teams`        | `(project, include_archived=False, refresh=False)` | Team areas (times) of a CCM project area, from ONE call to the Process REST (`GET {ELM_URL origin}/ccm/process/project-areas/{paId}/team-areas`, `Accept: text/xml`); the `paId` comes from the project's service provider URL. Returns `{"items": [{"name", "id", "uri", "process_uri", "archived"}], "total"}`, sorted by `name` (case-insensitive); archived teams only with `include_archived=true`. `uri` (`{origin}/ccm/oslc/teamareas/{id}`) is the value of `rtc_cm:teamArea`: pass it as `custom_fields={"rtc_cm:teamArea": {"rdf:resource": uri}}` in `create_workitem`; `set_field` sends `value` as a plain string for a field without `allowedValues`, so writing the team with it through `create_workitem(custom_fields=...)` was validated live on 24/nov/2026 (`set_field` was not tried live for it; by reading the code it would send a plain string). `process_uri` is `{origin}/ccm/process/team-areas/{id}` (`process:teamArea`). Blocks without a name or URL, or whose URL is on another origin, are dropped; DTD/entity declarations are refused. Cached like the other discovery calls (`refresh=true` reloads). An HTTP error names the gate; it never returns an empty list as success. |
| `list_time`         | `(id)` | Time sheet entries of a work item: `{"id", "entries": [{entry_uri, person, date, hours, time_code}], "total_hours"}`. The server keeps time in milliseconds; hours have 2 decimals and null time is 0. `person` is the `dcterms:creator` URI. An item without sheet or entries returns `[]`. |
| `get_hours`         | `(item_ids=None, plan=None, project=None, group_by="person", max_entries=500)` | Hours of work items plus their direct children (the selection of `get_plan_items`; `project` is only needed with `plan`), read from the time sheets with at most 8 requests at a time. `group_by="person"` sums per creator; `"item"` sums per work item with `estimate_hours` and, for an item with `timeSpent` but no entries, uses its `timeSpent` and marks `without_entries`. Returns `groups`, `total_hours`, `items_counted`, `entries_read`, `partial`, `unread_entries`, `items_without_entries`, `errors` (`[{entry_uri, error}]`, left out of the totals) and `truncated`. `max_entries` goes from 1 to 5000 (above is refused). Cost: 2N+1 GETs for N work items plus one GET per entry read; an entry listed by two items is read and counted once. Above `max_entries` it stops reading and returns the partial result without error; `partial` is also true when an entry failed to read (`errors`). An invalid `group_by` or `max_entries < 1` is refused. |
| `list_attachments`  | `(id)` | Attachments of a work item: `[{uri, name, identifier, format, creator, created}]` (`size` when the server reports it). `name` has no `<id>: ` prefix. Only metadata is read. |
| `download_attachment` | `(id, attachment, dest, overwrite=False)` | Saves one attachment to a **local** file; it never writes to the ALM (only GET requests), but it creates or replaces a **local** file with content from the ALM, so it is **not** read only (`readOnlyHint=false`, `destructiveHint=true`): clients must ask before running it. With `ELM_DOWNLOAD_DIR` set, `dest` must be inside that directory (symlinks and `..` resolved) or the call is refused. The whole download has a deadline (`ELM_DOWNLOAD_TIMEOUT`, default 300 s; the temporary file is removed). The file gets mode 0666 minus the umask; a name over 255 bytes is cut keeping the extension and control characters are dropped from the name; a write error (permission, disk full, name too long) is reported as an error, never as a traceback. `attachment` is the identifier, the exact name or the URI; `dest` is an existing directory (the file takes the server's name, base name only: `../` and `/` are dropped) or a file path. The content is requested with `Accept: */*` (other types answer 406). An existing file is refused unless `overwrite=True`. The size is capped by `ELM_MAX_DOWNLOAD_MB` (default 50); a refused, failed or expired download leaves no file. Returns `{"path", "size"}`. |

## Discovery

Read-only introspection of a project area's metadata. Use these **before** writing, so a create/update
fills the fields the server actually requires — nothing is hardcoded per project.

| Tool | Signature | Description |
|------|-----------|-------------|
| `list_types`       | `(domain, project, refresh=False)` | List resource types available in a project area. `rm`/`qm`: `[{"title", "shape_uri", "resource_type"}]`. `ccm`: one item per work item type creation factory, `[{"title", "id", "factory_title", "factory_uri", "shape_uri", "resource_type"}]`; `id` is the type id used by `list_fields` and `create_workitem`. `refresh=true` ignores the discovery cache. |
| `list_fields`      | `(domain, project, type, refresh=False)` | List required/optional fields of a type, with `allowedValues` when the field is enumerated. `type` is a shape title from `list_types` (case-insensitive); for `ccm` it is the type `id` or `title` from `list_types`, or a short alias (`task`, `story`...). Returns `{"type", "shape_uri", "required":[...], "optional":[...]}`; each field has `name`, `title`, `occurs` (e.g. `Exactly-one`), `read_only`, `property_uri`, `range_uri` and `allowed_values` (`[{"value_uri", "title"}]`). A value with no title in the `allowedValues` document, on the ELM server under `/oslc/enumerations/`, gets its `title` from that enumeration (one read per enumeration, cached like the other discovery calls, the URL built from the value URI; DTD/entity refused); the `title` is `null` when not resolved (enumeration unreadable or over 5 MB, literal absent from the document, value outside `/oslc/enumerations/`, a path segment that is not `[A-Za-z0-9_.-]+` or has `.`/`..`, or a URI with userinfo). `refresh=true` ignores the discovery cache. |
| `inspect_workitem` | `(id)` | Read a real work item and derive its shape/factory URIs and filled fields. Returns `{"id", "type", "shape_uri", "factory_uri", "fields":{...}}`. Useful to learn a project area's concrete field values from an existing item. |
| `list_folders`     | `(project)` | List RM (DOORS Next) folders for a project (queried by the project area URI). Returns `[{"title", "uri", "subfolders_query"}]`: only real folders (`nav#folder`), including the root folder (a valid `folder` parent for `create_requirement`); `subfolders_query` is the URI of the child-folder query, or `null` (informational, not navigable yet). Fails with "project area not advertised by the service provider" when the project does not announce its project area (`oslc:details`). |

## Write (RM requirements)

| Tool | Signature | Description |
|------|-----------|-------------|
| `create_requirement` | `(project, title, content, folder=None, type=None, if_exists="error", content_format="html")` | Create a requirement in a DOORS Next (RM) project. `content` is stored in `jazz_rm:primaryText` as XHTML with exactly one root `div`, read per `content_format`: `html` (default, sanitized; `script`/`style`/`iframe`/`object`/`embed` and characters above U+FFFF removed), `xhtml` (only validated and wrapped; refused if not well-formed; does NOT remove active content such as `script`) or `markdown` (own converter: headings, lists, tables, code, emphasis, links and images by http/https/mailto URL; raw HTML escaped); another value is refused before any request. Content above `ELM_RM_MAX_CONTENT_BYTES` (default 1048576) and, in `html`/`xhtml`, comments, CDATA and processing instructions are refused; an unclosed `<script>x` in `html` removes everything up to the end; Markdown URLs accept one level of balanced parentheses. If the creation POST is refused with 403 and the content exceeds `ELM_RM_CREATE_FALLBACK_BYTES` (default 4096; zero, negative or invalid uses 4096), the requirement is created without text and the content applied by PUT with `If-Match` (accepted 2xx; the re-read confirms the requirement exists and its ETag changed, the content is not compared); the result then has `content_applied` (`false` plus a `warning` when the PUT failed: the requirement exists, nothing is deleted). `folder` is a folder URI (`nav:parent`, from `list_folders`). `type` is **required at runtime** (the schema keeps it optional so the refusal can list the valid types): a shape URI or a type title, both from `list_types("rm", project)`; without it (or with an unknown title) the call is refused listing the valid types. Before the POST it queries (with the configuration context) a requirement of the same type and folder and the same title: the server filters by the EXACT title (case and inner spaces count; only edge spaces of the request are dropped) and the comparison after `strip`, whitespace collapse and `casefold` is applied only to the titles that come back, so it never widens the query. The query asks for up to 1000 items; if it is truncated the creation is refused (`duplicate check truncated`) unless `if_exists="create"`. `if_exists="error"` (default) refuses naming its URI and identifier, `"return"` returns it with `created: false` without writing, `"create"` creates anyway; a failed check refuses the creation (except `create`); a timeout after the POST queries again and never resends. With no `folder`, a requirement in any folder matches (accepted false positive: give `folder`, or use `"return"`/`"create"`). Returns `{"uri", "identifier", "created"}` read back from the server; if that re-read fails after the POST, the requirement exists anyway and the result carries a short `warning` (do not create it again). |
| `update_requirement` | `(uri, title=None, content=None, content_format="html")` | Update a requirement via OSLC PUT with ETag. `content` is read per `content_format` (`html`, `xhtml` or `markdown`, as in `create_requirement`) and never gets a doubled root `div`. Returns `{"uri", "identifier"}`, the identifier re-read from the server; after the accepted PUT (2xx) the re-read must show a new ETag, otherwise the result carries a `warning` (the content is not compared). A failed re-read never raises; the result carries a `warning`. |
| `delete_requirement` | `(uri)` | Delete a requirement via OSLC DELETE (direct mode, irreversible) and confirm by re-reading it (404 or 410). The DELETE is unconditional (no `If-Match`). Fails if it is still readable, and reports "deletion not confirmed" when the confirmation read is denied (401/403; the DELETE was sent). Returns `{"uri", "deleted": true}`. |

## Write (CCM work items)

| Tool | Signature | Description |
|------|-----------|-------------|
| `create_workitem`     | `(project, title, type="task", description=None, parent_id=None, owner=None, filed_against=None, custom_fields=None, if_exists="error")` | Create a work item by POSTing to the creation factory of the type. Before the POST it looks up a work item of the same type, normalized title and parent (`if_exists` as in `create_requirement`; the title filter is exact on the server, the normalized comparison is applied to what it returns). Missing required fields are filled from the local profile (`defaults.<type id>`; the explicit argument and `custom_fields` win) and any the shape still requires are refused, listed, before any write. The result carries `created`. `type` is any type of the project: the `id` or `title` from `list_types`, or a short alias (`task`, `story`...); an unknown type is refused listing the available ones. `owner` is stored in `dcterms:contributor`. If `filed_against` is omitted, it is not sent and the server applies its own default; the iteration is auto-discovered. A refused creation surfaces the server's message in the error, with a `list_fields` hint when it concerns the category. When the message says `The 'X' attribute needs to be set`, the hint names the shape property whose title is X (exact, then case-insensitive) and its number of allowed values, e.g. `(property <name> (7 allowed values))`; with no matching field the generic `filedAgainst` hint is kept. A 400 or 409 on the POST drops the project area's cached discovery, rediscovers it, runs the duplicate check again (an item the server created before answering is returned with `created: true` and a `warning`, nothing is resent) and resends once only if nothing new appeared (with `if_exists="create"` it resends without the check); keys of `custom_fields` given as a full property URI are normalized to `prefix:name`; names with accents (`classificação`) may come decoded, as `prefix:encoded` (`classifica%C3%A7%C3%A3o`) or as a full URI: they are written decoded, and a name that is not a plain `prefix:name` is refused; 403, 404 and 500 are not retried. |
| `update_workitem`     | `(id, title=None, description=None, owner=None, estimate_hours=None, planned_for=None, custom_fields=None)` | Partial update: PUTs only the given properties (`?oslc.properties=...`) with `If-Match`; `custom_fields` keys are normalized as in `create_workitem` (accented names are written decoded; an invalid name is refused). A stale ETag (412) is reported as a conflict. `owner` is stored in `dcterms:contributor`. |
| `add_child_workitem`  | `(parent_id, title, project, type="task", description=None, owner=None, if_exists="error", filed_against=None, custom_fields=None)` | Create a work item linked as a child of `parent_id`; delegates to `create_workitem`, so `if_exists`, `filed_against` and `custom_fields` behave the same. |
| `transition_workitem` | `(id, action)` | Execute a workflow action on a work item (`PUT ?_action=<id>`) and re-read its state. `action` is an alias of the local profile (`action_aliases`), or the id of a workflow action, its id suffix (e.g. `a27`), or a unique case-insensitive substring of the id; `start`/`resolve`/`close`/`reopen` work only where the workflow's action ids contain those words. An unresolved or ambiguous `action` lists the available ids; an action that does not change the state is an error. Returns `Work item {id}: {from} -> {to} (action: {action id})`. |
| `add_comment`         | `(id, text)` | POST the comment as OSLC CM 1.0 (`application/x-oslc-cm-change-request+json`, no `OSLC-Core-Version`: the 2.0 endpoint answers 405) and confirm it in `list_comments`. Returns the new comment. If the server accepts the POST but the comment does not appear, the call fails and the POST is **not** resent (check the item before retrying). |
| `link_workitems`      | `(source, target, link_type)` | Add a link from `source` to `target`: partial PUT of `rtc_cm:com.ibm.team.workitem.linktype.<type>` with `If-Match`, resending the links of that type already there; confirmed by re-reading `source`. `link_type`: `parent` (`parentworkitem.parent`, replaces the current parent), `blocks` (`blocksworkitem.blocks`), `depends_on` (`blocksworkitem.dependsOn`), `related` (`relatedworkitem.related`), `duplicate_of` (`duplicateworkitem.duplicateOf`), `resolves` (`resolvesworkitem.resolves`). An unknown type is refused listing the valid ones. |
| `unlink_workitems`    | `(source, target, link_type)` | Remove only that link (the PUT resends the remaining links, an empty list for the last one); confirmed by re-reading. A target that is not linked is an error, nothing written. |
| `link_artifacts`      | `(source_uri, target_uri, link_type)` | Link a work item (the source must be a CCM work item URI, otherwise refused before any request) to an RM/QM artifact: partial PUT of `oslc_cm:<link_type>` with `If-Match`, resending the targets already there; confirmed by re-reading the source. `link_type` (closed list): `implementsRequirement`, `tracksRequirement`, `affectsRequirement`, `testedByTestCase`, `relatedTestCase`, `relatedTestScript`, `relatedTestPlan`, `relatedTestExecutionRecord`, `affectsPlanItem`, `affectedByDefect`, `affectsTestResult`, `blocksTestExecutionRecord`, `relatedChangeRequest`. Same server only; source and target must differ; an existing link is `changed: false` with no PUT. Write validated live on 24/nov/2026 for `implementsRequirement`, `affectsRequirement` and `testedByTestCase` (link, unlink, re-read; repeating a link returned `changed: false`, checked only for `implementsRequirement`); the other types of the list are not yet exercised live. |
| `unlink_artifacts`    | `(source_uri, target_uri, link_type)` | Remove only that target (the PUT resends the rest); a target that is not linked is an error, nothing written. |
| `set_field`           | `(id, field, value)` | Partial PUT of one field with `If-Match`. `field` is the prefixed property (`rtc_cm:storyPoints`) or the shape's property name (`storyPoints`). Accented names work decoded (`classificação`, `rtc_ext:...classificação`) or as `prefix:encoded` (`rtc_ext:...classifica%C3%A7%C3%A3o`, as the shape declares it); the key is always written decoded, and a name that is not plain is refused. For an enumerated field `value` is the label (`5 pts`, as in `list_fields`: exact, else case-insensitive; a label shared by several values, or an id that is also the label of another value, is refused as ambiguous: pass the full URI to disambiguate), the literal id or the full URI, validated against `allowedValues` (a value outside them is refused listing the valid labels). Returns `{"id", "field", "value", "warnings"}`; writing `Unassigned` to a required attribute adds a warning (the server treats it as empty). |

## Write (ETM / QM test resources)

Status: creation (all four types, after the typed-body fix #78), editing, links, deletion and coverage were validated live against a real ETM on 24/nov/2026 (disposable items, all deleted). Only the title and description are written; the ETM may require data outside OSLC for other types. These types are DEFERRED and refused by create and update: `TestExecutionRecord`, `TestResult`, native script steps (`TestScriptStep`) and every type not listed below (`delete_qm_resource` does not filter by type). The 16/nov probe that created a `TestCase` used a typed node, not this tool: the tool sent an untyped `rdf:Description`, which the ETM refuses with 400 (#78). The POST body is now one typed node (`oslc_qm:TestCase`/`TestPlan`/`TestScript`, `rqm_qm:TestSuite`, `rdf:about=""`). Creation through this tool was confirmed live on 24/nov/2026 (TestCase, TestPlan, TestSuite and TestScript created and deleted).

| Tool | Signature | Description |
|------|-----------|-------------|
| `create_qm_resource` | `(project, type, title, description=None, if_exists="error")` | Create a `TestCase`, `TestPlan`, `TestSuite` or `TestScript` by title (and description). The creation factory is chosen by the `oslc:resourceType` local name (`oslc_qm` and `rqm` namespaces), never by title or position; no factory, two factories or a factory outside the ELM origin are refused before any write. The title and description are XML-escaped and lose control characters; an empty title is refused; limits: title 255 characters, description 32768. `if_exists`: `error` refuses a resource of the same type with the same normalized title (the query is not filtered on the server and is refused if truncated at 1000 items, unless `create`), `return` hands it back with `created: false`, `create` skips the check. After a timeout the POST is never resent: the title is queried again. Returns `{"uri", "short_id", "created"}` (`short_id` re-read from the `Location`; a failed re-read adds a `warning`). |
| `update_qm_resource` | `(uri, title=None, description=None)` | Re-read the resource (RDF/XML + `ETag`), change only the title and/or description and PUT the complete RDF with `If-Match`. Everything else the server sent is kept byte for byte. A resource without ETag, of a deferred type, outside the ELM origin or not a QM resource is refused; a 412 is a `[conflito]` error and is not retried. A weak ETag (`W/"..."`) is refused, and so is a title/description kept as an XML attribute of the node. Limits: title 255 characters, description 32768. A DTD or entity declaration in the answer is refused. After the PUT the resource is read again and the title/description are compared (whitespace/CRLF differences tolerated; properties added by the server tolerated, lost ones not). If that confirmation fails or disagrees, the error says that the PUT SUCCEEDED and the resource WAS changed, and not to retry blindly. Returns `{"uri", "updated"}`. |
| `delete_qm_resource` | `(uri)` | DELETE a QM resource (irreversible, unconditional) and confirm by re-reading it (404 or 410). A confirmation read denied (401/403) reports that the deletion was not confirmed. Returns `{"uri", "deleted": true}`. |
| `link_test_case` | `(test_case, target, link_type)` | Add `oslc_qm:<link_type>` to a TestCase: `validatesRequirement` (target = RM requirement) or `testsChangeRequest` (target = CCM work item), same server only. Re-reads, adds the link keeping every other property and link, PUTs the complete RDF with `If-Match` and confirms that the final set of that link type equals the expected one; if that re-read fails or disagrees the error says the PUT SUCCEEDED and the test case WAS changed. Targets with a query, fragment, `%` or `..` are refused; a weak ETag is refused. An already linked target is `changed: false` with no PUT. Returns `{"test_case", "target", "link_type", "changed"}`. |
| `unlink_test_case` | `(test_case, target, link_type)` | Remove only that target (same PUT and confirmation). A target that is not linked is an error, nothing written. Refused (nothing written) when the test case has a reified `rdf:Statement` whose `rdf:object` is that target, since removing only the link would leave it behind. |

## Errors

A failed HTTP call surfaces as a `ToolError` that starts with the gate that probably blocked it, then the
status, the operation and the action to take. The main reads and all writes re-authenticate once on a 401 or on a 403
without `oslc:message` before reporting (a few direct reads do not yet: see "Dívida conhecida" in `docs/roadmap.md`). A login that answers 403 or 5xx fails with `credencial` or `http-<status>`.

| Gate | Status | Meaning / action |
|---|---|---|
| `credencial` | 401 at login | Invalid user or password: check `ELM_USER` / `ELM_PASSWORD`. |
| `sessao` | 401 after login | Session expired and re-authentication did not help: retry. |
| `regra-de-processo` | 403 with `oslc:message` | A process rule refused the write; the server message is repassed unchanged. |
| `permissao` | 403 without message | Role, license or project area visibility insufficient. |
| `recurso-inexistente-ou-invisivel` | 404 | The URI does not exist or the project area is not visible to the user. |
| `conflito` | 412 | The resource changed since it was read: re-read and retry. |
| `formato` | 406 | The server does not offer the format (QM only answers RDF/XML). |

Other statuses are reported as `[http-<status>]` with the server message, if any. Credentials, cookies and
the `Authorization` header never appear in the message.

## Notes

- **Discover before you write.** `create_requirement`/`create_workitem` need shape and field values
  that vary per project area. Use `list_types` → `list_fields` (and `list_folders` for RM, or
  `inspect_workitem` to copy a real item's values) first. Nothing about a specific organization is
  baked into the package (see `docs/ARCHITECTURE.md`, core vs adaptation).
- `ELM_MAX_DOWNLOAD_MB` (default 50) caps `download_attachment`. `ELM_DOWNLOAD_DIR` (optional) confines its `dest` to one root. `ELM_DOWNLOAD_TIMEOUT` (seconds, default 300) is its global deadline.
- In `list_time` and `get_hours`, `person` is the URI of the user (`dcterms:creator`).
- Discovery (provider, factories, shapes, allowedValues, workflow, RM stream) is cached in memory per server and project area for `ELM_CACHE_TTL` seconds (default 300; a negative, `nan` or infinite value also means 300; `0` turns it off, read on every call); nothing about credentials or cookies is stored. `refresh=true` on `list_types`, `list_fields` and `list_workflow` reloads it.
- Local profile (ADR-005): plain JSON outside the package, in `ELM_MCP_PROFILE_DIR` (default `~/.elm-mcp/profiles/`): `templates/<name>.json` and `project-areas/<project area id>.json` (`"template": "<name>"` inside). Keys: `defaults.<type id>` (`{"rtc_cm:filedAgainst": {"rdf:resource": "..."}}`, values as in `custom_fields`), `action_aliases`, `hidden_states`. The template applies first, the project area over it: dicts merge key by key, lists and scalars of the project area replace. `elm-mcp profile draft <project>` prints a draft (required fields per type with `null` to fill, allowed values under `_review`) from read-only discovery.
- `create_requirement` requires `type`: pass the `shape_uri` or the title from `list_types` on the `rm` domain.
- `create_workitem` resolves the type from the project's own discovery (the same data as `list_types`), so custom
  types work without code changes (`docs/specs/SPEC-wi-custom-types.md`).
- `custom_fields` injects project-specific RDF attributes; values are discovered per project area
  (via the discovery tools), not hardcoded.
- QM (ETM) reads and the title/description writes are in the tables above; cross-domain links are
  `link_artifacts` (from a work item) and `link_test_case` (from a test case). See the `elm-qm` and
  `elm-traceability` skills.
- State changes go through `transition_workitem` (workflow action), not `update_workitem`.

- **Same origin only.** URLs followed from server responses (next pages, workflow states, comment and iteration
  references, shapes) and the URI of `get_requirement`/`get_resource` must have the same scheme, host and port as
  `ELM_URL` (`assert_same_origin`); anything else fails before a request is sent. A redirect (3xx) to another origin is
  refused before it is followed, by a response hook on the HTTP client. Use the exact public URL as `ELM_URL`.
- `set_field` integer ranges (`integer`, `int`, `long`, `short`, `byte`, `negative/nonPositive/nonNegative/positiveInteger`,
  `unsigned*`) take plain ASCII digits with optional sign (no `1_000`, no Unicode digits) and the sign of the range is enforced.

## Flat dict from RDF/XML (`get_resource` on RM)

`get_resource` asks for JSON first. The HTTP 415 fallback to `application/rdf+xml` applies **only to RM URIs** (path starting with `/rm/`); a 415 on any other URI (e.g. `/ccm/`) is reported as an error without a second call. The main `rdf:Description` is the one whose `rdf:about` equals the requested URI (else the first one). A malformed body, or one with a DTD/`<!ENTITY>`, raises `ValueError` (reported as a tool error).

Limitations of the flat dict (lossy by design):

- `rdf:nodeID` references and nested child nodes (a property whose value is an inline `rdf:Description`) are not preserved; such a property yields its text, usually empty.
- `rdf:datatype` is dropped: typed literals come back as plain strings.
- `rdf:parseType="Literal"` is returned as an XHTML string (`<div xmlns="http://www.w3.org/1999/xhtml">...</div>`) rebuilt from the parsed tree, not the original bytes (whitespace between attributes and namespace declarations may differ).
